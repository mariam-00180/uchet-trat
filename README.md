## Настройка приложения

Приложение использует переменные окружения, указанные в файле `.env`:

```dotenv
PORT=8080
DB_PATH=expenses.db
SESSION_SECRET=замените-на-длинный-случайный-секрет
```

- `PORT` — порт HTTP-сервера.
- `DB_PATH` — путь к файлу базы данных SQLite.
- `SESSION_SECRET` — секретный ключ, используемый для вычисления HMAC-SHA256 при создании хэша токена сессии.

Перед запуском необходимо создать файл `.env` на основе `.env.example` и указать собственное длинное случайное значение `SESSION_SECRET`.

**Важно:** не публикуйте файл `.env` и не передавайте секретный ключ другим лицам. Сохраняйте одинаковое значение `SESSION_SECRET` между запусками приложения. При изменении ключа существующие сессии могут стать недействительными, и пользователям потребуется войти снова.

## Миграции базы данных

SQL-файлы миграций находятся в каталоге `migrations`.

При запуске приложение выполняет миграции в порядке имён файлов. Успешно выполненные миграции записываются в таблицу `schema_migrations`, чтобы не выполнять их повторно при каждом запуске.

Перед изменением существующей базы данных рекомендуется создать резервную копию. Для проверки установки с нуля следует использовать отдельный файл базы данных, не удаляя исходную базу `expenses.db`.

## Проверка проекта

Откройте терминал в каталоге проекта, где находится `go.mod`, и выполните:

```powershell
gofmt -w *.go
go test ./...
go vet ./...
go run .
```

- `gofmt` форматирует исходный код Go.
- `go test ./...` проверяет сборку и запускает доступные автоматические тесты.
- `go vet ./...` проверяет код на некоторые потенциальные ошибки.
- `go run .` запускает веб-приложение.

Сообщение `[no test files]` означает, что в пакете нет автоматических тестов. Оно не подтверждает, что все функции приложения проверены.

## Сценарий демонстрации

1. Регистрация нового пользователя и вход в систему.
2. Добавление расходов с указанием категорий.
3. Редактирование и удаление расходов.
4. Фильтрация по категории и диапазону дат.
5. Просмотр статистики по категориям и месяцам.
6. Экспорт расходов в CSV.
7. Проверка обработки некорректных данных.
8. Перезапуск приложения и проверка сохранности данных.
9. Проверка того, что разные пользователи видят только собственные расходы.

## Резервное копирование и безопасность

Перед обновлением проекта рекомендуется создать резервную копию базы данных.

Файл `.env` и локальная база данных `expenses.db` не должны публиковаться в открытом репозитории. Для примера настроек используйте `.env.example`, не содержащий реальных секретов.

Пароли новых пользователей сохраняются в виде хэшей bcrypt. Операции с расходами должны ограничиваться идентификатором текущего пользователя.
